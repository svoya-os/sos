# SOS identity files

Generated by `generate.py` from `branding/tools/brand.py` (name, version, codename). Edit there, then
run `python3 branding/os/generate.py`. Files under `root/` are laid out as they are installed:

| file | installed as | notes |
|---|---|---|
| `root/usr/lib/os-release` | `/usr/lib/os-release`, plus the symlink `/etc/os-release → ../usr/lib/os-release` | the systemd/Debian convention; `base-files` is diverted or replaced by `svoya-branding` |
| `root/etc/lsb-release` | `/etc/lsb-release` | read by `lsb_release` and older tools |
| `root/etc/upstream-release/lsb-release` | same path | the engine underneath (Ubuntu 26.04 LTS), Linux Mint's convention |
| `root/etc/issue`, `root/etc/issue.net` | same paths | console and network login banners |
| `root/etc/motd` | `/etc/motd` | static tail printed after Ubuntu's dynamic `update-motd.d` parts |

## Why these values

* `NAME="SOS"`, `ID=sos`, `PRETTY_NAME="SOS 26.10 «Первый сигнал»"`: the owner's decision (2026-09-25).
  `PRETTY_NAME` is UTF-8 and quoted, which os-release(5) allows. Tools that show one line (GNOME About,
  fastfetch, `hostnamectl`) print it as is.
* `ID_LIKE="ubuntu debian"`: the engine is Ubuntu 26.04 LTS. Tools that do not know `sos` fall back to
  the Ubuntu and then Debian code path. That covers `ubuntu-drivers`, NVIDIA's and AMD's installers,
  the CUDA and ROCm repository scripts, Docker's and Steam's installers, `distro`/`platform` in Python,
  and packaging helpers that branch on the distro family. The order matters: `ubuntu` before `debian`.
* `VERSION_CODENAME=signal` is ours. `UBUNTU_CODENAME=resolute` tells the tools that build apt source
  lines which Ubuntu archive to use (they read `${UBUNTU_CODENAME:-$VERSION_CODENAME}`). Without it
  they would try `…/ubuntu signal main` and fail. Scripts that only call `lsb_release -cs` still get
  `signal`. If a third-party installer breaks on that, point it at `/etc/upstream-release/lsb-release`
  as Mint does, rather than giving up our codename.
* `LOGO=sos`: the icon name in `/usr/share/icons/hicolor/*/apps/sos.png` and `scalable/apps/sos.svg`
  (from `branding/logo/icon/`), used by GNOME About, fastfetch and systemd's welcome screen.
* `ANSI_COLOR="1;37"`: neutral bright white. The console is a pre-login surface and carries no accent
  (design/DESIGN.md §12), so it can never clash with the accent the user picks. `/etc/issue` reuses it
  through agetty's `\S{ANSI_COLOR}`.
* The URLs point at the placeholder repository `https://github.com/svoya-os/sos`. `PRIVACY_POLICY_URL` links
  the published promise in `docs/VISION.md` (no telemetry).

## Paths stay `svoya`

User-facing strings say SOS / «СОС». Technical names keep the `svoya` namespace: packages `svoya-*`, the
command `svoya`, `/usr/share/svoya/…`, `/etc/svoya/`, the Plymouth theme `svoya-signal`, the GRUB theme
`svoya`, and the sound theme `svoya` (docs/ARCHITECTURE.md). The one exception is the icon name `sos`,
because `LOGO=` names an icon, and that icon is the product mark.

## Console

`/etc/issue` shows `··· ——— ···` in bright white, then the pretty name, then `host · tty · kernel`
in half-bright. The console font must contain `·` and `—`. Set `CODESET="Uni2"` in
`/etc/default/console-setup` (Ubuntu's default for ru/en) or use a Terminus font. `issue.net` is plain ASCII.
