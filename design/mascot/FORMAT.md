# Jackson sprite format — `sos-jackson/1`

Files: `shell/assets/jackson/imp.json`, `shell/assets/jackson/cat.json` (generated by `design/mascot/build.py`,
do not edit by hand). Reference runtimes: `design/mascot/jackson.js` (JavaScript, port this to the QML Canvas)
and `design/mascot/render.py` (Python). Both are tested against each other (2 430 combinations of looks, states,
system accents and custom colours: identical grids and palettes).

A sprite is 32×32 pixels. Every pixel is a one-character **key**; every key maps to a named **slot**; slots get
colours from the character, the skin, the accent and the theme mode. Options (style, hood, headphones, glasses,
skin overlays) are separate **layers**; a small **compose** recipe says which layers to draw, in which order.
No image files, no per-combination sprites: any look × any state × any accent costs one 32×32 pass.

## Top-level keys

| key | meaning |
|---|---|
| `format` | `"sos-jackson/1"` |
| `id`, `name` | `"imp"` / `"cat"`, `{ru, en}` |
| `size` | `32` |
| `slots` | `{key: slotName}` — `"."` is transparent and never listed |
| `fixed` | `{slotName: "#rrggbb"}` — colours that never change for this character |
| `skins` | `{skinId: {name:{ru}, colors:{slotName: hex}, flags:[…]}}` — skin overrides `fixed`; `flags` switch layers (`"points"` = siamese mask) |
| `accents` | `{accentId: {name:{ru,en}, dark:{…}, light:{…}}}` — precomputed `detail`, `detailShade`, `detailLight`, `outfit`, `outfitShade`, `outfitLight` for the 8 system accents |
| `aliases` | `{slot: otherSlot}` — slots that follow another slot unless set (`led → detail`) |
| `stateSlots` | `{state: {slot: otherSlot}}` — per-state overrides (`error: led → headphonesLight`, LEDs go dark) |
| `options`, `defaults` | allowed values and defaults of the look options (same keys as `~/.config/svoya/avatar.json`) |
| `derive` | `{name: [{when:{…}, value}, …, {value}]}` — derived options, first matching rule wins |
| `compose` | ordered list of steps (below) |
| `tint` | `{keys:"owY", to:"e"}` — how tinted lenses show the eyes |
| `animations` | shell mood → frames and durations (below) |
| `states` | `{state: [32 strings of 32 keys]}` — the face and props of each state |
| `layers` | `{layerName: [32 strings of 32 keys]}` |

States: `idle`, `blink`, `listening`, `thinking`, `talk1`, `talk2`, `happy`, `error`.

## Compose (per frame)

```
o = derive(defaults ∪ userOptions ∪ {state})
grid = 32×32 of null
for step in compose:
    skip if step.when doesn't match o            (value or list of allowed values)
    skip if step.skinFlag not in skins[o.skin].flags
    step.layer   → name = step.layer with {option} placeholders filled from o; if layers[name] exists:
                   copy every non-"." key into grid
    step.outline → every null pixel with a non-null 4-neighbour becomes step.outline   (one pass)
    step.state   → copy states[state] the same way
    step.tint    → for every non-"." pixel p of layers[name]: grid = (grid in tint.keys) ? tint.to : p
```

Everything before the `outline` step is the silhouette (body, hood, head, headphones, horns); the state layer,
lit cups and glasses come after it, so props (sparkles, thought bubbles, sound arcs, sweat) have no outline.
Missing layer names are simply skipped — e.g. `glasses.none`, or `hood.` when the style isn't a hoodie.

## Colours (per frame)

```
c = fixed ∪ skins[o.skin].colors
c ∪= detail*  from accents[systemAccent][mode]        (custom accent: detailFor(hex))
c ∪= outfit*  from: o.outfit == "accent"   → accents[systemAccent][mode]
                    o.outfit == accentId   → accents[accentId][mode]
                    o.outfit == "#hex"     → outfitFor(hex, mode)
for slot, alias in aliases:          c[slot] ??= c[alias]
for slot, alias in stateSlots[state]: c[slot] = c[alias]
pixel colour = c[slots[key]]
```

`mode` is `dark` for Graphite and Phosphor, `light` for Paper. `outfitFor` (DESIGN §13): OKLCH lightness
0.32 / 0.25 / 0.40 (dark) or 0.45 / 0.36 / 0.56 (light), hue kept, chroma capped at 0.075 (dark) / 0.11 (light),
then reduced until the colour fits sRGB. Dark oranges and yellows turn to mud-brown, so inside the hue band
35°…115° the cap dips smoothly: `cmax × (1 − 0.4 × cos((h − 75°) / 40° × 90°))` (Signal/Amber at night → a warm
coffee hoodie, not mustard). `detailFor`: the accent itself, a shade (L −0.13, or −0.08 for dark
accents) and a highlight (L +0.12 max). Both are ~30 lines in `jackson.js`; the 8 accents never need them.

## Animation

```json
"idle":      {"frames": ["idle", "blink"],  "ms": [3600, 120], "jitter": [2400, 0]}
"talking":   {"frames": ["talk1", "talk2"], "ms": [140, 140]}
"listening" | "thinking" | "happy" | "error": one frame
```

`jitter` adds a random 0…N ms to that frame so blinks don't look mechanical. The shell's mood → state mapping
stays as in `JacksonAvatar.qml` (`speaking` → `talking`, `working` → `thinking`, happy beat → `happy`).
Reduce motion: show frame 0 only.

## Rendering in QML (suggested)

* Parse both JSON files once (≈ 40 KB each). Keep `layers`/`states` as arrays of strings.
* Draw at integer scales only: 32 px (panel head, toasts, launcher row), 64 px (control center), 128 px (wizard),
  192 px (customizer). 24 px — the toast size in DESIGN §13 — is 0.75× and smears the pixels; the mockups use
  32 px in toasts (proposed §13 change). On 2× displays 16 px is also crisp (one sprite pixel = one device pixel).
* Canvas of `32 × scale` (scale = 1 in the panel head at 32 px, 4 in the wizard, 6 in the customizer);
  `renderStrategy: Canvas.Cooperative`, `smooth: false`. Draw with `fillRect(x*s, y*s, s, s)` per pixel
  (≤ 1024 rects), or put the composed frame into an `ImageData` and scale with nearest-neighbour.
* Cache the composed grid per `(character, options, state)` and the palette per `(options, state, mode,
  accent)`; an accent or theme change only re-maps colours (no re-compose). Recompute on
  `avatar.json`, accent or theme change — the 260 ms cross-fade can simply fade two canvases.
* Backing: in the panel head and toasts draw the sprite on a `surface3` rounded square (radius 8 at 32 px),
  per DESIGN §13. Sprites never get an outline glow or blur.

## Adding a look option later

Add a layer (or a set named with a placeholder, e.g. `hat.{hat}`), add one `compose` step, add the option to
`options`/`defaults`. Existing clients that don't know the option use the default and keep working.
